# AI_BOT

## О проекте

AI_BOT — это Telegram-бот на Node.js, который поддерживает:
- обычного бота с командами и голосовой обработкой;
- пользовательский userbot для работы с аккаунтом Telegram;
- режим аккаунт-ассистента с черновиками и утверждением ответов.

Репозиторий использует CommonJS и `.env` для конфигурации.

## Команды и веб-панель Orbit AI

Требуется Node.js 22.13+. Единый реестр содержит 80 записей: 70 видимых команд Telegram, 51 веб-команду, 8 userbot-команд и 2 служебные записи. Все исходные команды сохранены. Полный список и примеры: [docs/command-catalog.md](docs/command-catalog.md). Архитектура, результаты проверок и границы внешних интеграций: [docs/command-system-report.md](docs/command-system-report.md).

```powershell
npm install
npm run web
```

Открой `http://127.0.0.1:12723`: поиск, категории, избранное, недавние команды, светлая/тёмная тема, реальные инструменты и игровые сценарии. `npm start` подключает тот же интерфейс к основному серверу на `PORT` и запускает Telegram. Не запускай два polling-процесса с одним токеном.

Telegram: `/start` → `/menu` → категория → команда. Если нужны параметры, выбери команду и отправь обычный текст. Примеры: `/quiz`, `/calculator (12+8)*3`, `/notes add Идея`, `/todo add Прочитать книгу`, `/timer 5m`, `/reminder 10m Сделать перерыв`, `/favorite quiz`.

Данные новых команд и настройки аккаунта хранятся в `data/commands.sqlite` (переопределение: `COMMAND_DB_FILE`). Веб и Telegram имеют отдельные пользовательские области. Для удалённой веб-панели нужен отдельный `WEB_ACCESS_TOKEN`; за HTTPS-прокси установи `WEB_SECURE_COOKIE=true`. AI требует `OPENROUTER_API_KEY`; локальные команды работают без него. Погода использует настоящий Open-Meteo.

```powershell
npm test
npm run check
npm run test:e2e
npm run commands:catalog
# Платные реальные запросы OpenRouter, без отправки Telegram-сообщений:
npm run test:live:commands
```

Playwright настроен на установленный Microsoft Edge. Таймеры и напоминания выполняются при запущенном приложении. Веб-уведомления появляются в открытой панели; push в закрытый браузер не реализован. Команды аккаунта требуют действующей Telegram-сессии: по результатам проверки 14.10.2026 текущая сессия не авторизована, поэтому для реальной работы нужно заново выполнить `npm run telegram:session`.

## Интерактивные ответы AI

Вопросы с конкретными вариантами ответа отображаются с кнопками под сообщением Telegram. Модель сама определяет вопрос, число вариантов, их подписи и полные значения. Поддерживаются одиночный выбор и множественный выбор с отметками и кнопкой «Подтвердить». Открытые вопросы остаются обычным текстом; написать свой ответ можно всегда.

Нажатие передаёт `value` в тот же механизм AI-диалога, который обрабатывает текст и расшифрованные голосовые сообщения. Выбор сохраняется с ролью `user` в истории. Telegram Bot API не позволяет боту отправлять сообщения от имени человека: в самом Telegram бот показывает подтверждение «Твой ответ», затем продолжение AI. Фотографии также могут вызывать интерактивные вопросы.

Поддержка OpenRouter определяется по каталогу выбранной модели: JSON Schema при наличии `structured_outputs`, Tool Calling при наличии `tools`, JSON Object при наличии `response_format`, иначе JSON по инструкции. Служебные ответы проверяются до отображения; повреждённый формат получает одну попытку исправления, после чего остаётся обычный текстовый режим. UI-инструмент только описывает вопрос и никогда не запускает произвольные инструменты или код модели.

В `src/services/interactiveQuestion.js` определена единая схема `interactive_question` с полями `question`, `selection_mode`, `options` (`id`, `label`, `value`) и `allow_custom_input`; необязательное `text` содержит пояснение перед вопросом. Ручной ввод остаётся доступным, даже если модель ошибочно передала `allow_custom_input=false`.

Состояние вопросов хранится в `interactive-state.json`: принадлежность чату и пользователю, ID сообщения, выбранные варианты, обработанные callback ID, стадия отправки и сохранённое продолжение AI. Старые или завершённые кнопки не создают новых запросов после перезапуска. Ошибка доставки позволяет явно повторить отправку; уже полученный ответ AI и подтверждённые части Telegram-сообщения используются повторно без новых генераций и дублей истории. Обновление клавиатуры само по себе не вызывает AI.

Длинные списки разбиваются на страницы по шесть вариантов. Подписи сокращаются для удобства, полные значения сохраняются. Верхние пределы защищают от чрезмерных ответов модели: 100 вариантов, 200 символов в подписи, 1000 символов в значении. Это нативные кнопки Telegram; их шрифты, цвета, мобильное отображение и навигацию клавиатурой определяет клиент Telegram.

Дополнительные настройки:

```env
OPENROUTER_STREAM=false
INTERACTIVE_STATE_FILE=./interactive-state.json
INTERACTIVE_QUESTION_TTL_MS=86400000
```

При `OPENROUTER_STREAM=true` ответы и аргументы UI-инструмента собираются из SSE-фрагментов. Кнопки появляются после завершения и валидации ответа; незаконченный JSON не отправляется в Telegram. По умолчанию сохраняется обычный непотоковый режим.

Проверки:

```bash
npm test
npm run check
npm run test:live:interactive
```

Последняя команда делает реальные запросы OpenRouter и может расходовать баланс. Она проверяет основные модели из конфигурации, три сценария диалога, Structured Outputs, Tool Calling, JSON Object, резервный формат, streaming и изображение. Результаты и тестовая память сохраняются во временном каталоге, указанном в выводе. Отдельной сборки и TypeScript-проверки в проекте нет.

Для проверки настоящих нажатий в разрешённом личном чате:

```bash
node scripts/check-interactive-telegram.js --chat-id YOUR_USER_CHAT_ID
```

Проверка задаёт два вопроса с кнопками и один открытый вопрос, ожидает настоящие ответы пользователя, проверяет историю и останавливает временный polling. Её нужно запускать при остановленном основном polling-процессе бота. ID должен принадлежать человеку, а не самому боту. Тестовые сообщения и история изолированы от рабочей памяти.

## Быстрый старт

1. Скопируйте `.env.example` в `.env` и заполните значения.
2. Установите зависимости:

```bash
npm install
```

3. Запустите основного бота:

```bash
npm start
```

4. Для режима `userbot` используйте:

```bash
npm run userbot
```

5. Для генерации Telegram session используйте:

```bash
npm run telegram:session
```

## Зависимости

Проект использует следующие пакеты:

- `@neondatabase/serverless` — вспомогательные инструменты для работы с базами данных и серверлесс-средой;
- `@vercel/speed-insights` — утилиты для измерения производительности и аналитики;
- `axios` — HTTP-клиент для запросов к внешним API;
- `dotenv` — загрузка переменных окружения из `.env`;
- `express` — веб-сервер для проверки состояния и простых HTTP-эндпоинтов;
- `node-telegram-bot-api` — библиотека для Telegram-бота;
- `telegram` — библиотека для Telegram userbot и работы с пользовательской сессией.

## Структура проекта

- `index.js` — основной вход приложения.
- `scripts/userbot.js` — запуск Telegram userbot.
- `scripts/create-telegram-session.js` — генерация `TELEGRAM_STRING_SESSION`.
- `src/bot.js` — инициализация обычного бота, регистрация обработчиков, запуск Express-сервера.
- `src/commands.js` — команды Telegram и интерфейс кнопок.
- `src/handlers/` — обработчики голосовых, фото и текстовых сообщений.
- `src/services/` — интеграции с Telegram, OpenRouter, памятью и аккаунт-ассистентом.
- `src/config.js` — загрузка и валидация переменных окружения.

### Сервер и поддомен

Для постоянной работы достаточно сервера с Node.js и службы `systemd`; поддомен для polling не требуется. Для webhook задайте `HOST=127.0.0.1`, `WEBHOOK_URL=https://bot.example.com`, `WEBHOOK_PATH=/telegram-webhook` и секрет `WEBHOOK_SECRET_TOKEN` (сгенерируйте его командой `openssl rand -hex 32`). DNS A-запись поддомена должна указывать на внешний IPv4 VPS, а Caddy проксирует HTTPS на `127.0.0.1:12722`.

Пошаговый шаблон установки на Ubuntu находится в [`deploy/ubuntu/README.md`](deploy/ubuntu/README.md). Не запускайте одновременно локальную и серверную копии с одним токеном бота.

## Как пользоваться

### Обычный бот

Запустите `npm start`, затем используйте бота в Telegram. В боте доступны команды и кнопки меню.

### Userbot

Запустите `npm run userbot`, чтобы подключиться как пользователь Telegram и обрабатывать входящие сообщения от имени аккаунта.

Userbot поддерживает команды в диалоге с вашим аккаунтом:

- `.help` — показать список команд
- `.ping` — проверить связь
- `.say <текст>` — повторить текст
- `.echo <текст>` — дублировать текст
- `.whoami` — информация об аккаунте
- `.status` — состояние userbot
- `.chatid` — ID текущего чата
- `.time` — текущее время

### Account assistant

Account assistant работает на фоне обычного бота и обрабатывает входящие сообщения аккаунта Telegram.
Для владельца доступны команды управления через основной бот:

- `/account_help` — список команд аккаунт-ассистента
- `/account_status` — статус аккаунт-ассистента
- `/account_config` — текущие настройки
- `/account_pending` — активные черновики
- `/account_send id` — отправить черновик
- `/account_drop id` — отклонить черновик
- `/account_reply id текст` — отправить свой ответ
- `/account_redraft id` — пересоздать AI-черновик
- `/account_message @username текст` — отправить сообщение от аккаунта
- `/account_mode approval|auto|dry-run` — посмотреть или сменить режим
- `/account_private true|false` — включить/выключить личные чаты
- `/account_allow @username` — добавить разрешённый контакт
- `/account_block @username` — заблокировать контакт
- `/account_enable` — включить ассистента
- `/account_disable` — отключить ассистента

При получении черновика владельцу будут приходить inline-кнопки: Отправить, Редрафт, Отклонить и Заблокировать отправителя.
Команды управления аккаунт-ассистентом и bot-to-bot доступны только в личном чате с ботом от Telegram-пользователя, чей ID указан в `ACCOUNT_ASSISTANT_OWNER_CHAT_ID` или `BOT_TO_BOT_OWNER_CHAT_ID`. ID общей группы для этих переменных не подходит.
Дополнительные переменные окружения:

```env
USERBOT_START_MESSAGE=Userbot started.
USERBOT_SEND_SELF=false
```

### Создание сессии

Для создания `TELEGRAM_STRING_SESSION` используйте команду:

```bash
npm run telegram:session
```

Следуйте инструкциям в консоли и сохраните выданное значение в `.env`.

## Команды

Обычный бот поддерживает команды:

- `/start` — показать главное меню;
- `/help` — помощь;
- `/menu` — открыть меню;
- `/voice` — информация о голосовом вводе;
- `/status` — статус модели и памяти;
- `/reset` — очистить память чата.

Команды аккаунт-ассистента:

- `/account_status` — статус ассистента аккаунта;
- `/account_pending` — черновики ответов;
- `/account_send <id>` — отправить черновик;
- `/account_drop <id>` — отклонить черновик;
- `/account_reply <id> текст` — отправить пользовательский ответ.

Команды bot-to-bot:

- `/bot_status` — статус режима bot-to-bot;
- `/bot_send текст` — отправить сообщение целевому боту в `BOT_TO_BOT_CHAT_ID`;
- `/bot_send @username текст` — отправить сообщение указанному боту.

## Полезные проверки

Если запуск падает:

1. Проверьте `.env` на наличие обязательных переменных.
2. Повторно выполните `npm install`.
3. Запустите `npm start` или `npm run userbot` снова.
4. Если `src/config.js` сообщает об ошибке, проверьте `.env` на пустые значения и исправьте их.

Если `BOT_TOKEN` или `OPENROUTER_API_KEY` пусты или неверны, исправьте `.env` и не запускайте бота с неполной конфигурацией.

## Диагностика

- `npm install` — устанавливает зависимости.
- `npm start` — запускает обычного бота.
- `npm run userbot` — запускает пользовательский аккаунт-бот.
- `npm run telegram:session` — создает Telegram-сессию.

Если что-то не работает, сначала проверьте `.env`, затем повторите `npm install`, и только после этого изучайте логи и `src/config.js`.

## Важно

Храните `TELEGRAM_STRING_SESSION` в секрете — это ваша авторизованная сессия Telegram.
