# Аудит и модернизация системы команд — 14 октября 2026

Изменения внесены в исходный проект `AI_BOT/AI_BOT`. Telegram-бот, аккаунт-ассистент, отдельный userbot, текст, голосовые, изображения, память и ранее созданный протокол AI-вопросов сохранены. Ранее существовавшие незакоммиченные изменения сохранены; `.env`, пользовательская история, `memory.json.bak` и сессии не редактировались этой задачей. Коммит, push, деплой и запуск нового production polling не выполнялись.

## Реестр и архитектура

Полный перечень: [command-catalog.md](command-catalog.md), машинный формат: [command-catalog.json](command-catalog.json). Реестр содержит 80 записей: 70 видимых Telegram-команд, 51 веб-команду, 8 команд отдельного userbot и 2 служебные записи. Сохранены 25 исходных видимых команд бота, скрытая `/bot_chat` и 8 userbot-команд. Добавлены 45 видимых команд и внутренний `select` для множественного выбора.

Каждая запись содержит ID, название, описание, категорию, иконку, JSON-схему входа, пример, handler, доступные интерфейсы и, при необходимости, ограничение владельца и внешний сервис. Уникальность ID проверяется при регистрации. Ошибки одного обработчика возвращают структурированный ответ и не завершают приложение. `execute` применяет валидацию, последовательную обработку сессии, журнал результата без пользовательского текста и постоянную защиту от повторного ID запроса.

Входной контракт — `{ "args": "текст параметров" }`; лишние поля, объекты вместо строки и чрезмерный ввод отклоняются. Обработчики проверяют собственную грамматику и диапазоны. Ответ — JSON с текстом, проверенными кнопками, полем следующего ввода и, для QR, PNG. Модель может предложить только текст и варианты ответа из ограниченного протокола; имена исполняемых команд и пользовательский код из ответа модели не выполняются.

SQLite хранит заметки, задачи, игровые сессии, избранное, недавние команды, ожидаемый ввод, непрозрачные кнопки, результаты запросов, настройки и черновики аккаунта, напоминания и доставленные веб-уведомления. Записи пользователей разделены по интерфейсу и сессии; Telegram дополнительно разделяется по чату и пользователю. Заметки, задачи и основные игры изменяются в транзакциях. Старый разговорный контекст Telegram сохраняет прежний контракт истории чата.

## Исправленные проблемы

- Разрозненная регистрация заменена общим реестром и единым slash-диспетчером. Userbot использует тот же исполнитель со своей областью доступности.
- Команды с неверными аргументами больше не исчезают из строгих regex без ответа. Неизвестные команды и запрет доступа возвращают объяснение.
- Команды, обычный AI-диалог и старые AI-кнопки Telegram используют общую очередь чата, чтобы `/reset` не конфликтовал с генерируемым ответом. Новый запуск инвалидирует старые вопросы.
- Исправлены неперехваченные ошибки отправки из обработчиков текста, фото, аудио и account callback.
- Настройки и черновики аккаунт-ассистента переживают перезапуск. Для восстановленного черновика peer разрешается заново по chatId.
- Отправка, редрафт и удаление черновика защищены от конкурирующих нажатий. Истёкшие черновики не отправляются. Если перезапуск прервал отправку, повтор заблокирован до проверки целевого чата.
- Редрафт обновляет текст и сохраняет рабочие кнопки. Ранее принудительно скрывались кнопки после обновления.
- Черновики не записываются в историю как отправленные сообщения. История добавляется после фактической отправки; редрафт не создаёт фиктивную переписку.
- Throttling аккаунта ожидает интервал внутри очереди вместо молчаливого удаления входящего сообщения. После ожидания повторно проверяются включение и разрешения.
- Включение аккаунт-ассистента фиксируется после успешного подключения; состояние подключения учитывает `isConnected`.
- Поле `sendable` принимает только boolean; произвольный JSON, лишние поля и неверные типы не разрешают автоотправку.
- Сетевой сбой отправки аккаунта больше не вызывает безусловную повторную отправку без replyTo. Повтор допустим только при явной ошибке Telegram в ссылке на исходное сообщение.
- Пустой ответ модели `{}` или `[]` получает одну попытку исправления; повторный пустой объект считается ошибкой. Регрессия обнаружена на реальном `/review` и повторно проверена.
- OpenRouter больше не является обязательным для запуска локальных инструментов; при отсутствии ключа AI-команды честно сообщают о настройке.
- Ошибки провайдеров журналируются без полного response body, внутренних user_id, токенов и содержимого диалога.
- Небезопасные транзитивные HTTP-зависимости обновлены через совместимые overrides, сохранив используемый API `node-telegram-bot-api@0.67`. Реальный `getMe` подтвердил совместимость транспорта. `npm audit`: 0 уязвимостей.

Перевод без указанного языка уточняет язык назначения. Regex-помощник объясняет выражения и не исполняет произвольные регулярные выражения пользователя. Fact-check, poll и другие пункты из примеров задания не добавлены как неработающие карточки: реализован выбранный набор команд с настоящими обработчиками. `/chat` — явный интерфейс существующего AI-диалога.

## Интерфейсы

Веб-панель Orbit AI: адаптивные карточки, категории, поиск по названию/описанию/ID, избранное, недавние команды, пример с одной кнопкой вставки, форма параметров, состояние выполнения, активная карточка, ошибки, копирование ответа, скачивание QR, динамические варианты и подтверждение множественного выбора. Светлая/тёмная тема сохраняется в браузере; учтён reduced motion. Вывод через `textContent` предотвращает выполнение HTML из текста пользователя или AI. Проверены ширины 320, 390, 768, 1024 и 1440 px.

Telegram: `/start` устанавливает Reply Keyboard; `/menu` показывает категории Inline Keyboard. Кнопки создаются из реестра и серверных ответов. Opaque callback ID ограничен 64 байтами, связан с пользователем, чатом и сообщением, хранится в SQLite и используется один раз. Ввод параметров запоминается, поэтому после выбора инструмента можно отправить обычный текст. Поиск, избранное, недавние команды и главное меню доступны кнопками. Владелец видит защищённые команды аккаунта; прежние account-кнопки и `menu:` callbacks поддерживаются. Цвета и анимации Telegram определяет сам клиент, а не бот.

Веб-сессия сохраняется HttpOnly cookie на 30 дней; CSRF, проверка Origin, ограничение числа запросов и максимального JSON тела защищают API. По умолчанию API доступно только локально. Для удалённого доступа обязателен отдельный `WEB_ACCESS_TOKEN`; он вводится через форму и не сохраняется в localStorage. Веб-сессия не даёт права управлять Telegram-аккаунтом.

Реальная сессия аккаунта вернула `Account session unauthorized`. Поэтому настоящая отправка, auto-reply и owner-операции аккаунта не объявляются проверенными. Требуется создать новую сессию через `npm run telegram:session` и установить `TELEGRAM_STRING_SESSION` в `.env`. Подключение проверялось без отправки сообщений.

Сохранённая основная STT-модель вернула HTTP 404; рабочая резервная модель успешно распознала WAV «The answer is forty two». Следует выбрать доступную `OPENROUTER_STT_MODEL`, хотя fallback уже работает. Структурная корректность и доступность модели не гарантируют фактическую точность любого AI-ответа.

Живые нажатия и доставка в пользовательском Telegram-чате, реальное bot-to-bot общение, webhook production и VPS в этой задаче не проверены. Telegram-транспорт подтверждён чтением `getMe/getWebhookInfo`; локальные callbacks и handlers проверены тестами. Для финального чата потребуется его явно заданный ID и работающий экземпляр бота. Один токен должен обслуживаться одним polling-процессом.

Планировщик работает каждую секунду при запущенном приложении; после перезапуска обрабатывает просроченные записи. Веб-уведомления видны при открытой панели и обновляются каждые 15 секунд; push и фоновых уведомлений закрытого браузера нет. Standalone веб-процесс обрабатывает только веб-напоминания; Telegram-напоминания доставляет основной бот. При ошибке сети есть до пяти попыток и статус `failed`; запись можно отменить. SQLite lease снижает риск конкурентной обработки. Telegram Bot API не поддерживает ключ идемпотентности доставки, поэтому сетевой обрыв после принятия сообщения может дать неопределённый результат; абсолютная exactly-once гарантия не заявляется.

## Запуск

Требуется Node.js 22.13+; в этой задаче проверки выполнены на Node 24.21.0. Отдельная компиляция не требуется: CommonJS и статический frontend.

```powershell
cd D:\Проекты\AI_BOT\AI_BOT
npm install
npm run web
```

Веб-панель: `http://127.0.0.1:12723`. При `npm start` та же панель доступна на основном `PORT` (по умолчанию 12722) вместе с Telegram-ботом.

```powershell
npm start
# Отдельный userbot, при авторизованной сессии:
npm run userbot
# Проверки:
npm test
npm run check
npm run test:e2e
npm run commands:catalog
# Следующая команда делает платные реальные запросы OpenRouter:
npm run test:live:commands
```

Для Telegram нужен `BOT_TOKEN`. Для AI — `OPENROUTER_API_KEY` и доступная модель `OPENROUTER_MODEL`. Погода использует Open-Meteo без дополнительного ключа; условия использования сервиса следует проверить для коммерческого развёртывания. Для аккаунта нужны `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, действительная `TELEGRAM_STRING_SESSION` и `ACCOUNT_ASSISTANT_OWNER_CHAT_ID`. Для внешнего веб-доступа — `WEB_ACCESS_TOKEN`, HTTPS-прокси и `WEB_SECURE_COOKIE=true`. Путь базы задаётся `COMMAND_DB_FILE`; без настройки это `data/commands.sqlite`.

Примеры: `/quiz`, `/calculator (12+8)*3`, `/notes add Идея для выходного`, `/todo add Прочитать книгу`, `/reminder 10m Сделать перерыв`, `/qr https://example.com`, `/favorite quiz`, `/weather Kyiv`. Для нового local-инструмента добавляется одна запись в реестр и тест; основные адаптеры менять не требуется.
