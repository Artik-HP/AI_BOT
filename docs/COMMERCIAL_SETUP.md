# Основа коммерческого AI_BOT

Бот готовится к продаже как продукт: закрытый доступ, PostgreSQL-учёт пользователей, отзыв доступа и конфигурируемое имя. Оплата, тарифы, лицензирование установок и автоматическая выдача подписок остаются отдельными этапами.

## Вход и хранение

Пользователь отправляет `/start` в личный диалог, вводит пароль и получает меню. Сообщение с паролем поглощается до AI, истории и логирования и по возможности удаляется из Telegram-чата. `/logout` отзывает сессию; `/login` начинает новый вход. Сессии действуют 8 часов по умолчанию, находятся в памяти процесса и сбрасываются после перезапуска.

`BOT_PASSWORD_HASH` содержит только salted scrypt-хеш. Пароль и хеш не публикуются в Git, документации, health или логах. Отсутствующий/неправильный хеш закрывает доступ. После пяти ошибок действует блокировка на 15 минут; есть глобальное ограничение ошибочных попыток и максимум две одновременно работающие hash-проверки. Сессия привязана к Telegram ID. Анонимные отправители не могут войти, группы не используются для ввода пароля.

Знание пароля не даёт роль владельца. Роли задаются существующими OWNER-параметрами, allow-list остаётся дополнительным ограничением. Bot-to-bot и фоновый account-assistant требуют живой сессии соответствующего владельца. Standalone userbot сохраняет отдельную проверку Telegram-аккаунта/разрешённых ID.

JSON-память и лаборатория сохраняют существующие форматы. Автоматического переноса старых пользовательских диалогов в PostgreSQL нет.

## PostgreSQL и VPS

Runtime-зависимость: `pg`. `@electric-sql/pglite` находится только в devDependencies и нужен SQL-тестам. Production-установка его не требует.

В закрытом серверном `.env` задаются `HOST=127.0.0.1`, `PORT=12722`, `PRODUCT_NAME`, `DATABASE_URL` и `BOT_PASSWORD_HASH`. Не публикуйте секреты в переписке или командах. Используйте уже подготовленный серверный URL и локально настроенный хеш. Для удалённого PostgreSQL требуется `sslmode=verify-full`; loopback допускает соединение без TLS. Проверка сертификата автоматически не отключается.

Из каталога Linux-релиза с доступным секретным окружением:

```bash
npm ci --omit=dev --ignore-scripts
npm run db:migrate
npm run db:check
```

CLI читает `.env` из текущей папки. Для `shared/config/.env` создайте штатную закрытую ссылку `.env` в релизе либо передайте переменные через менеджер процессов. Используйте того же приложенческого пользователя и окружение, что и PM2. Нужен один процесс бота: Telegram polling и сессии принадлежат одному экземпляру.

Миграция `001_commercial_accounts.sql` применяется транзакционно под advisory lock и регистрируется в `ai_bot.migrations`. Повторный запуск не создаёт дубли. Добавляются только схема `ai_bot` и таблицы:

- `users`: Telegram ID, active/blocked, access_until, даты создания/входа;
- `access_events`: кто и кому изменил доступ, действие, дата;
- `migrations`: версия схемы.

Первый правильный пароль создаёт активного пользователя. Существующий blocked/истёкший доступ пароль не обходит. Ошибка настроенной базы или отсутствующая миграция не дают новую сессию. Пул ограничен пятью соединениями; есть тайм-ауты; значения передаются параметрами SQL. Миграции не запускаются автоматически вместе с polling.

Без DATABASE_URL можно проверять автономный парольный вход; PostgreSQL-команды честно сообщают об отсутствии подключения. Это не файловая подмена PostgreSQL и не подтверждение production-подключения.

## Управление пользователями

- `/me` — свой статус.
- `/users` — последние 30 пользователей, только владельцу в личном чате.
- `/access ID blocked` — подготовить отключение.
- `/access ID active 30` — подготовить доступ на 30 дней.
- `/access ID active` — активировать без ограничения даты.

Изменение требует отдельной кнопки подтверждения, привязанной к владельцу, сообщению, сессии и сроку. Общего «да» недостаточно. После изменения старая сессия пользователя закрывается. Собственный доступ этой командой не меняется. Для немедленного отзыва используйте `/access`; внешнее редактирование SQL само по себе не заменяет отзыв сессии работающего процесса.

## Проверки и состав релиза

```bash
npm run check
npm audit --omit=dev
git diff --check
```

Runtime-файлы: `index.js`, `src/**`, `migrations/**`, `scripts/database.js`, действующие scripts userbot/session при необходимости, `package.json`, `package-lock.json`. Документацию можно включить отдельно. Исключите `.env`/`.env.*`, Telegram-сессии, реальные memory/lab JSON, Windows node_modules, `.local`, архивные artifacts, tests, test-results и devDependencies. Постоянные данные хранятся вне релиза; `MEMORY_FILE` и `AI_LAB_FILE` указывают на shared/data.

Telegram/OpenRouter проверяются локальными HTTP-фейками. PGlite проверяет PostgreSQL-семантику SQL на изолированном WASM-движке; это не проверка TCP, SCRAM, TLS или роли VPS. Эти live-проверки выполняются в процессе развёртывания.
