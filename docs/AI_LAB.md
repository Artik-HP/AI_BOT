# AI-лаборатория

Модуль работает через существующий Telegram-бот. Веб-панель в этом checkout отсутствует. Запуск приложения остаётся прежним; не запускайте второй polling-процесс с тем же токеном.

```powershell
Set-Location -LiteralPath 'D:\Проекты\AI_BOT\AI_BOT'
npm start
```

После запуска откройте личный диалог с ботом и отправьте `/lab`. Уже работающий экземпляр нужно обновлять штатным способом; эта разработка не перезапускает рабочие процессы и не выполняет деплой.

## Сценарии

### Идеи

Опишите задачу, пользователя, навыки и доступное время. Например: «Три небольших инструмента для магазина; знаю основы JavaScript, есть выходные». Бот запрашивает три карточки с проблемой, пользователем, вводом/выводом, MVP, стеком, оценкой усилий, проверкой полезности и ограничениями. Монетизация обозначается как гипотеза: поиска рынка в этом модуле нет.

Выбранную идею можно уточнить, превратить в план, разобрать её слабые стороны и сохранить. Сохранённый проект открывается в «Мои проекты», экспортируется в JSON и передаёт спецификацию генератору HTML-инструмента. Для проекта доступны экспорт и удаление с отдельной кнопкой подтверждения.

### Эксперименты

Введите задачу, общий пример данных, промпт A и промпт B по шагам. Ни на одном из этих шагов запрос к AI не отправляется. Предварительный просмотр показывает задачу, ввод, обе инструкции, выбранную модель и параметры. «Запустить: 2 генерации» сохраняет эксперимент и выполняет по одному запросу каждого варианта.

Для расширенных проверок вместо первого сообщения можно прислать JSON:

```json
{"task":"Описание товара","input":"Термокружка 400 мл","a":"Ответь кратко","b":"Перечисли преимущества","maxChars":500,"words":["400"],"json":false,"temperature":0.4}
```

`maxChars`, `words`, `json`, `temperature` необязательны. Температура ограничена диапазоном 0–1. Проверки длины, обязательных слов и JSON выполняются детерминированно. Качество оценивает пользователь; третий платный AI-судья не запускается. Каждый запрос имеет одинаковый общий ввод и не получает историю обычного чата.

Показываются фактический текст, время, модель и usage провайдера. Если модель или расход не возвращены, отображается «Нет данных». Стоимость не вычисляется по выдуманному тарифу. Ошибка одного варианта сохраняет результат другого. Отдельное подтверждение повтора запускает только незавершённые варианты. При тайм-ауте результат может быть неизвестен, а запрос мог быть оплачен. После перезапуска ничего не повторяется автоматически.

«Отмена» доступна во время генерации, не ожидает окончания основной очереди и предотвращает следующий шаг. Текущий отправленный запрос не отзывается у провайдера и может быть учтён. Одновременный запуск другого AI-действия в том же контексте отклоняется.

### Обучение

Выберите JavaScript или Python и уровень «с нуля» либо «базовый», введите цель и явно создайте трек. Это небольшой фиксированный курс из трёх занятий: переменные/условия/выражения или коллекции/циклы/функции. Произвольные темы не заявляются как готовые учебные курсы.

Каждый урок содержит объяснение, пример и отдельное задание на определение вывода. Ответ отправляется сообщением и проверяется автоматически. Короткие ответы проверяются по правилам; присланный код разбирает AI с привязкой к ID урока и попытки, без исполнения. Ошибочная или невалидная AI-проверка не закрывает урок. Подсказка и готовое решение доступны отдельными кнопками; их использование сохраняется. После правильного ответа можно явно перейти к следующему уроку.

Прогресс — число завершённых занятий из трёх, а не процент знания языка. Трек, попытки и текущий урок сохраняются и доступны после перезапуска. Дубликат попытки не увеличивает прогресс.

### Мини-инструменты

Выберите автономный HTML либо Node.js без сторонних пакетов и опишите назначение, ввод и ожидаемый результат. После просмотра спецификации нажмите «Сгенерировать». В ответ выдаётся файл с безопасным серверным именем, инструкцией, двумя примерами и ограничениями. Присланное моделью имя файла не используется. HTML не открывается в административной панели и не исполняется ботом; Node.js-результат предназначен для вывода в stdout без изменения исходных файлов.

Сервер проверяет JSON-схему, тип, размеры, завершённость ответа, HTML-обёртку и консервативный список неподдерживаемых конструкций. Это статическая проверка формата, не гарантия корректности или безопасности произвольного кода. Ответ с `finish_reason=length` либо без подтверждённого `stop` не выдаётся как готовый файл. Runtime лаборатории не содержит исполнителя кода, shell или установки зависимостей.

## Конфигурация

| Переменная | По умолчанию | Назначение |
|---|---|---|
| AI_LAB_ENABLED | true | Включить раздел, обработчики и пункт меню |
| AI_LAB_FILE | MEMORY_FILE + `.lab.json` | Отдельное локальное хранилище |
| AI_LAB_MODEL | пусто | Использовать общую модель; отдельное значение выбирается администратором |
| AI_LAB_MAX_TOKENS | 4000 | Предел ответа, допустимо 64–16000 |
| AI_LAB_TIMEOUT_MS | 60000 | Тайм-аут одного запроса, 100–120000 мс |
| AI_LAB_DAILY_REQUESTS | 30 | Резервируемые генерации на пользователя в сутки UTC, 2–200 |
| AI_LAB_MAX_BYTES | 10MB | Максимум JSON-хранилища |

Резерв числа генераций списывается перед операцией. Эксперимент резервирует два запроса; при отмене или ошибке резерв не возвращается. Это консервативное ограничение обращений, не денежный бюджет и не счёт провайдера. Очистка лаборатории не обнуляет лимит.

Дополнительные границы: 4 одновременно выполняемые AI-операции в процессе, одна на пользователя; вход до 8000 символов; 30 проектов, экспериментов, треков и артефактов каждого типа; до 100 попыток на трек; код артефакта до 48000 символов; HTTP-ответ лаборатории до 256 KiB. Более сложные задачи следует делить на небольшие инструменты. Поля и массивы AI-ответа ограничены отдельно.

## Хранение и доступ

`src/lab/store.js` — версионированный JSON v1, атомарная запись через временный файл с fsync, предыдущая проверенная версия в `.bak`. Хранилище отделено от `memory.json`; нормализатор обычной памяти его не затрагивает. Данные разделены по приватному chatId и userId. В группах лаборатория предлагает открыть личный диалог.

Поддерживается один процесс-писатель на локальной файловой системе. Второй процесс блокируется. После смерти владельца устаревший lock восстанавливается под отдельной блокировкой восстановления. Живой или непроверяемый владелец блокирует запись. Multi-host/сетевые файловые системы, принудительное удаление lock и аппаратная сохранность не подтверждены. При оставшемся `.lock.recovery` после аварии требуется ручная проверка процессов администратором; бот не удаляет непроверяемую блокировку автоматически.

При повреждении основной записи оригинал сохраняется как `.corrupt-*`, если есть валидная резервная копия. Без проверенной копии модуль отказывает в записи и не затирает файл. Это не миграция обычной памяти и не изменение её формата.

Выбранная идея сохраняется только кнопкой; трек — после «Создать учебный трек». При запуске сохраняется эксперимент, при генерации — артефакт. Тексты черновиков находятся в памяти до 30 минут; при перезапуске их нужно ввести снова. Сохраняется только признак активной лаборатории/ID урока для правильной маршрутизации. Не вставляйте секреты в запросы. Экспорт маскирует известные конфигурационные секреты, но не является универсальным детектором неизвестных секретов в пользовательском тексте.

«Экспорт лаборатории» содержит свои проекты, треки, эксперименты и файлы, без callbacks/служебных операций. Удаление проекта удаляет связанные файлы и обновляет текущую резервную копию. «Очистить лабораторию…» требует отдельной кнопки и удаляет свои результаты, сохраняя дневной счётчик и минимальную дедупликацию. Исторические `.corrupt-*` и внешние резервные копии не стираются; это не обещание физического безвозвратного удаления с диска.

Callbacks одноразовые, привязаны к пользователю, приватному чату, сообщению и актуальному экрану; срок — 24 часа. Служебные операции содержат ID исходного события, статус, время и безопасный код ошибки, без промпта; дедупликация ограничена 7 днями и 500 последними операциями контекста. После аварии выполнявшаяся операция становится `unknown`; платный повтор всегда требует нового действия.

## Проверки

```powershell
Set-Location -LiteralPath 'D:\Проекты\AI_BOT\AI_BOT'
npm run check
git diff --check
```

Новый runner обнаруживает только актуальные тесты в `tests/unit` и `tests/integration`, исключая вложенные архивные приложения. Стенд запускает дочерний процесс из временной папки, поэтому реальный `.env` не загружается. В Windows тесты graceful shutdown передают тестовый IPC-сигнал, вызывающий JS-обработчик SIGTERM; это проверка пути остановки, а не доказательство доставки нативного сигнала ОС. Проверка EADDRINUSE использует искусственно неудачный первый запуск и реальный второй процесс.

Модель `openai/gpt-6.1-sol` присутствовала в публичном каталоге OpenRouter при подготовке этой поставки. Это подтверждение каталога, а не оплаченного вызова, доступности на пользовательском аккаунте или всех возможностей модели. Общая модель и настоящий `.env` не менялись.

Живой Telegram, оплаченная генерация OpenRouter, production-деплой, UI реального Telegram-клиента и произвольные AI-сгенерированные программы требуют отдельных проверок. Контролируемый HTML/Node.js-калькулятор в тестовых fixtures проверяется как пример; его результаты не переносятся на любое будущее сгенерированное приложение.
