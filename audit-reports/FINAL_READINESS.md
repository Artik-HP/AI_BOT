## Что именно проверено, а что нет

**Проверено (запускалось, результат виден):**

* `npm run check` = ESLint + 163 теста: зелёный на Node 22.22 и Node 20.20 локально;
* **CI на GitHub Actions** (PR #3, коммит `cc34770`): Node 20, 22, 24 и `npm audit --audit-level=high` — все четыре задачи `success`;
* `npm audit`: 0 уязвимостей; `npm ci --dry-run`: lock-файл согласован;
* те же 56 e2e-тестов на оригинальном коде: 43 падают, 13 (регрессионные) проходят; на новом коде 56 из 56;
* мутационная проверка: 38 поломок фиксов, 38 обнаружены тестами (37 в прогоне 2, ещё одна — после усиления теста в прогоне 3);
* фаззинг (500 апдейтов, воспроизводим по seed), стресс регулярных выражений на 1 МБ, большие файлы (аудио 18 МБ, фото 9 МБ), память 11 МБ;
* сканирование секретов в дереве и во всей истории.

**Не проверено и почему:**

| Что | Почему | Как проверить |
|---|---|---|
| Реальный Telegram Bot API и MTProto | `api.telegram.org` недоступен из среды | дымовой прогон (ниже) |
| Реальный OpenRouter: модели, STT-эндпоинт, лимиты | `openrouter.ai` недоступен | дымовой прогон (ниже) |
| `npm run telegram:session` | нужен настоящий номер телефона и код | вручную при создании новой сессии |
| devcontainer | нужен Docker | открыть репозиторий в devcontainer |
| Долгая работа (часы), утечки памяти | вне времени сессии | наблюдение за RSS после деплоя |

## Дымовой прогон после деплоя (5 минут, на тестовом боте)

1. `/start`, `/help` — ответ есть; в меню `/` нет служебных команд (у не-владельца).
2. Текстовый вопрос — ответ приходит; длинный ответ (попросить «напиши 5000 символов») приходит несколькими сообщениями.
3. Голосовое сообщение на 5–10 секунд — расшифровка и ответ. Если ошибка — менять `OPENROUTER_AUDIO_MODEL` (R3).
4. Фото с подписью — ответ по картинке.
5. С чужого аккаунта (если задан `BOT_ALLOWED_USER_IDS`) — один отказ, второго нет в течение минуты.
6. `GET /health` — `{ok, uptimeSec}` без списков; `GET /health/details` без токена — 404 или 401.
7. `kill -TERM <pid>` — в логе «Остановка (SIGTERM)…», код выхода 143, `memory.json` обновлён.
8. Если включён ассистент аккаунта: `/account_status`, затем сообщение с другого аккаунта — приходит черновик с кнопками, в режиме `approval` ничего не уходит само.

## Что дальше (по убыванию пользы)

1. Закрыть утечку: отозвать сессию, очистить историю, при необходимости перевыпустить токены (`REMAINING_ISSUES.md`, п. 1–4).
2. Дымовой прогон на тестовом боте; поправить `OPENROUTER_AUDIO_MODEL`.
3. Открыть репозиторий в devcontainer и убедиться, что `npm ci` и `npm run check` проходят.
4. Задать `BOT_ALLOWED_USER_IDS`, если бот не должен быть публичным.
5. Решить судьбу gramjs (R1) и добавить `LICENSE`.
