# Отчёт о модернизации (этап 4)

Дата: 2026-10-19. Ветка: `claude/full-audit-ai-bot`, точка отката: тег `pre-audit-baseline` (`e2a47fe`).

Принцип: каждая модернизация либо закрывает находку первичного аудита, либо измеримо улучшает
скорость/надёжность, и в обоих случаях покрыта тестом. Функциональность бота не менялась, кроме
тех мест, где старое поведение было дефектом (они перечислены в `FIXES_REPORT.md`).

## Что изменилось по областям

### Скорость и ресурсы

| Что | Было | Стало | Как проверено |
|---|---|---|---|
| Запись памяти | синхронная запись **всего** хранилища на каждое сообщение | отложенная асинхронная запись (одна на серию изменений, `MEMORY_SAVE_DEBOUNCE_MS`); атомарность «временный файл + `rename`» сохранена, копия раз в `MEMORY_BACKUP_INTERVAL_MS` | `evidence/after/perf-*.txt`, `tests/unit/memory.test.js` |
| Обработка сообщений при большой памяти | цикл событий блокируется на запись (до 2 с при ~11 МБ памяти; baseline под такой нагрузкой «подвисал») | запись вне горячего пути | `evidence/after/perf-compare.js`, `perf-burst.js` |
| Загрузка gramjs | всегда при старте (+37–40 МБ, +0,2 с) | лениво, только если включён ассистент аккаунта | `tests/integration/account-assistant.test.js` («gramjs не загружается…») |
| Голос, ошибка STT | каскад из 5 запросов с полным аудио на любой ошибке, включая «неверный ключ» | на 401/402/403/413 каскад останавливается сразу (1 запрос); по моделям он идёт дальше только при нефатальных ошибках (например, 404 «нет такой модели»); временные ошибки HTTP повторяются один раз | `bot-flow.test.js`, `service-errors.test.js` |
| Ответ модели | без `max_tokens` | `OPENROUTER_MAX_TOKENS` (1500 по умолчанию) | `bot-flow.test.js` |
| Подряд идущие сообщения контакта | теряются | объединяются в один черновик | `account-assistant.test.js` |
| Очередь задач по чатам | была (внутри `telegram.js`), но без возможности дождаться завершения при остановке | вынесена в `createKeyedQueue` с `whenIdle()`; порядок внутри чата сохранён, чаты идут параллельно, при shutdown ответы успевают уйти | `bot-edge-cases.test.js` (40 чатов × 3 сообщения), `bot-resilience.test.js` (SIGTERM во время обработки) |

### Надёжность и обработка исключений

* Все обработчики событий обёрнуты в `safeHandler`: исключение больше не превращается в
  `unhandledRejection` и не роняет процесс. Информационные сообщения отправляются через
  `trySendMessage` (заблокированный бот не ломает остальных пользователей).
* Единая модель ошибок: `ApiError` / `toSafeError` / `describeError` — в ошибке нет ни заголовков, ни
  конфигурации запроса, ни тела диалога; временные ошибки (`isTransientError`) повторяются один раз.
* Корректное завершение: `SIGINT`/`SIGTERM`/`SIGHUP` → остановка опроса (по-настоящему, см. F031),
  дожидание текущих ответов, отключение ассистента, закрытие HTTP-сервера, сброс памяти на диск,
  коды выхода 130/143/129, жёсткий таймаут 15 с.
* Повреждённый `memory.json` уходит в карантин `*.corrupt-<время>`, бот стартует с резервной копии
  или с пустой памятью, исходник не затирается.
* Ошибка запуска HTTP-сервера (порт занят) → понятное сообщение и ненулевой код выхода.
* Скачивание файлов: жёсткий лимит и по метаданным, и по фактическому размеру.

### Безопасность (модернизация сверх точечных фиксов)

* Контроль доступа `BOT_ALLOWED_USER_IDS` + скользящее окно `RATE_LIMIT_*`, владелец (`OWNER_CHAT_IDS`) не ограничен;
  отказ — одно сообщение в минуту на пользователя.
* `/health` публичный, но минимальный; подробности — только за `HEALTH_TOKEN` (сравнение через `timingSafeEqual`).
* Меню команд Telegram: публичные команды видят все, служебные — только владелец (scoped `setMyCommands`).
* Ассистент аккаунта: детерминированная проверка «опасного» авто-ответа (деньги, ссылки, секреты, реквизиты),
  авто-режим требует allow-list, имя отправителя очищается, в промпте помечено как недоверенный ввод.
* Userbot: команды только от владельца (и явно перечисленных ID), защита от зацикливания (нейтрализация префикса).
* Зависимости: `npm audit` — 0 уязвимостей (было 13, из них 3 critical), один lock-файл (`package-lock.json`),
  `overrides` для транзитивных `request`/`qs`/`uuid`.

### Логирование и наблюдаемость

* Единый логгер: уровни (`LOG_LEVEL`), ISO-время, автоматическое вырезание секретов (токен бота, ключ OpenRouter,
  `Bearer …`, строковая сессия), тексты сообщений по умолчанию не логируются (`LOG_MESSAGES=true` включает).
* Падение процесса больше не печатает `BOT_TOKEN` (проверено дампом `util.inspect(error, { showHidden: true })`).

### Конфигурация

* `buildConfig(env, warn)` — чистая функция, читатели типизированы (число/байты/булево/список/ID/URL/enum).
  Единицы `25MB`, `8mb`, `1.5GB` понимаются; мусорное значение даёт предупреждение и значение по умолчанию,
  а не молчаливое отключение лимита.
* `validateConfig` собирает **все** проблемы разом (заглушки `process.env.X`, неверный формат токена, пробелы в ключе).
* Новые настройки (все с безопасными значениями по умолчанию): `OPENROUTER_BASE_URL`, `TELEGRAM_API_BASE_URL`
  (нужны для тестов и прокси), `MAX_REPLY_PARTS`, `RATE_LIMIT_*`, `HEALTH_TOKEN`, `BOT_ALLOWED_USER_IDS`,
  `OWNER_CHAT_IDS`, `USERBOT_ALLOWED_USER_IDS` и др. — см. `.env.example`.

### Архитектура и код

* Разделение ответственности: `src/utils/*` (чистые функции: `text`, `errors`, `redact`, `logger`, `queue`, `ttlSet`, `safe`),
  `src/services/access.js` (допуск), `src/handlers/guard.js` (единая проверка для текста/голоса/фото/кнопок).
* Внедрение зависимостей в точке, где это нужно для тестов: `startAccountAssistant(bot, { createClient, createEventFilter })`.
* Удалён мёртвый и сломанный код (12 ошибок `no-undef`), посторонние файлы (`src/## GitHub Copilot Chat.md`,
  `src/SKILL.MD`, `scripts/package.json*`), две неиспользуемые зависимости (`@neondatabase/serverless`,
  `@vercel/speed-insights`) и второй lock-файл.

### Инфраструктура разработки

* ESLint (flat config) — `npm run lint`, 0 замечаний; тесты на встроенном `node:test` — `npm test`; всё вместе — `npm run check`.
* CI (`.github/workflows/ci.yml`): Node 20 / 22 / 24, lint + тесты + `npm audit --audit-level=high`.
* Dependabot: npm, GitHub Actions, devcontainer.

## Дополнения повторного аудита

* **Настоящая остановка опроса** (`stopTelegramPolling`): остановка за ~1 мс вместо «видимости остановки» (подробности — S2-04).
* **Повтор `getMe()`** при сбое на старте — иначе бот не знает своего имени и путает чужие команды со своими (S2-01).
* **Лог ошибок опроса** не чаще раза в минуту, со счётчиком пропущенных и подсказками про 409 (второй экземпляр) и 401 (токен) (S2-02).
* **Линейная обрезка пробелов** (`trimLineEnds`) вместо квадратичной регулярки (S2-03).
* **Инструменты проверки**, оставленные в репозитории для повторения: `evidence/after/mutation-check.js` (38 поломок фиксов),
  `baseline-control.sh` (те же e2e на оригинале и на новом коде), `perf-compare.js`/`perf-burst.js`, фаззинг-тесты `tests/integration/bot-fuzz.test.js`.

## Чего сознательно **не** делалось

| Идея | Почему нет |
|---|---|
| Обновить `node-telegram-bot-api` до 2.x | 2.x — полная переписка на ESM с другим API; риск несоразмерен пользе. Уязвимости закрыты через `overrides` |
| Перейти с long polling на webhook | меняет модель развёртывания (нужен публичный HTTPS) — решение владельца |
| Заменить gramjs (`telegram`) | пакет помечен как устаревший апстримом; миграция на форк не проверяема без живого Telegram — вынесено в `REMAINING_ISSUES.md` |
| Хранить память в БД | при текущем объёме достаточно атомарного файла; зависимость и миграция не оправданы |
| Менять модель по умолчанию для STT | нельзя проверить без доступа к OpenRouter; риск отмечен в `REMAINING_ISSUES.md` |
