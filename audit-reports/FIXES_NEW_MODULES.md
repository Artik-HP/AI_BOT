## N-12: что нужно знать до `git pull` и после слияния

1. **Сделайте копию перед `git pull`.** Когда вы заберёте коммит, где эти файлы убраны из индекса, git удалит их из вашей рабочей папки (а если вы их изменили — остановит `pull` с ошибкой). Скопируйте вне репозитория: `data/` (там может быть живая база команд `commands.sqlite` вместе с `-wal` и `-shm`), `.local/` и `artifacts/`. После `pull` эти пути в `.gitignore`, и вы можете вернуть копии на место — git больше их не тронет.
2. **Шаблоны развёртывания лежат только там.** В репозитории нет отслеживаемого `deploy/`: `Caddyfile.example`, `ai-bot.service.example`, `install.sh` и `bot.env.example` есть лишь внутри `artifacts/vps-production-smoke/ai-bot/deploy/ubuntu/` и в тарболах. Если нужной копии нет на вашем диске, достаньте её из истории: `git show 54c4afa:artifacts/vps-production-smoke/ai-bot/deploy/ubuntu/install.sh` (и так для каждого файла) и положите в отслеживаемый каталог по вашему выбору.
3. **История.** Файлы остаются в истории ветки `claude/full-audit-ai-bot` и в ссылке GitHub `refs/pull/3/head` (их оттуда может убрать только поддержка GitHub). Поэтому PR сливается **squash-коммитом**: в историю `main` попадёт одно итоговое состояние без этих файлов. Токен `WEB_ACCESS_TOKEN` из двух `config.env` смените, если он когда-либо работал на настоящем сервере; значение, похожее на ключ OpenRouter (не в формате `sk-or-…`), проверьте на сайте OpenRouter и при сомнении отзовите.
