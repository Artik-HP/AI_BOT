# ARCHITECTURE.md

## Обзор

`AI_BOT` — Node.js (CommonJS) с четырьмя режимами работы, которые живут в одном репозитории:

- `npm start` — основной бот (`index.js` → `src/bot.js`): `node-telegram-bot-api` с long polling, OpenRouter для ИИ, Express для health-check;
- ассистент аккаунта — модуль `src/services/accountAssistant.js`, подключается к вашему Telegram-аккаунту через gramjs (`telegram`) и отдаёт черновики владельцу через основного бота;
- bot-to-bot — общение с другим ботом (часть `services/telegram.js`);
- `npm run userbot` — отдельный процесс `scripts/userbot.js` с командами от вашего аккаунта.

## Поток обычного сообщения

```
Telegram → polling → bot.on("message")
  ├─ handlers/text|voice|photo   выбирает «свой» тип сообщения
  ├─ claimIncomingMessage        отсекает повторную доставку (по chat_id:message_id)
  ├─ handlers/guard.admitMessage люди: список допущенных + лимит запросов; боты: гейт bot-to-bot
  └─ enqueueChatTask(chatId)     один за другим в пределах чата, разные чаты параллельно
       └─ services/openrouter    запрос, один повтор при временной ошибке, санитизация ошибок
            └─ services/telegram sendAIResponse → splitMessage → sendMessage (части по ≤ 4096)
```

Любой обработчик событий обёрнут в `utils/safe.safeHandler`: `node-telegram-bot-api` не ждёт промисы обработчиков, и необработанная ошибка (например `403`, когда пользователь заблокировал бота) иначе завершила бы весь процесс. Глобальные `unhandledRejection` / `uncaughtException` и корректная остановка настроены в `src/bot.js`.

## Модули

| Путь | Роль |
|---|---|
| `index.js` | загрузка `.env`, запуск, понятная ошибка конфигурации вместо стека |
| `src/config.js` | разбор окружения (числа, байты `25MB`, булевы, списки, URL), заглушки, `validateConfig()` |
| `src/bot.js` | сборка приложения, Express (`/`, `/health`, `/health/details`), остановка, глобальные обработчики, регистрация модулей в `lifecycle` |
| `src/handlers/actions.js` | реестр inline-кнопок под ответами (`act:<токен>`): карточка искры и ответ с идеями; токены в памяти, одна клавиатура каждого вида на человека в чате |

| `src/commands.js` | единое описание команд (меню Telegram и `/help` строятся из него), кнопки, inline-меню |
| `src/handlers/` | `text`, `voice`, `photo` и общий `guard` (допуск, индикатор набора) |
| `src/services/telegram.js` | создание бота, дедупликация, гейт bot-to-bot, отправка с разбиением, скачивание файлов |
| `src/services/openrouter.js` | чат, vision, расшифровка голоса, черновики ассистента; ошибки наружу только как `ApiError` |
| `src/services/memory.js` | память чатов, профиль, системный промпт; отложенная атомарная запись, резервная копия |
| `src/services/access.js` | допущенные пользователи, владелец, лимит запросов |
| `src/companion/` | характер «собеседник»: `prompt.md` (текст автора), `persona.js` (сборка промпта и выбор характера), `engine.js` (ответ с вызовами функций), `tools.js` (восемь функций и общий `executeTool` для всех двенадцати), `hints.js` (подсказки модели к кодам отказа), `characters.js` + `rules.js` (правила RPG), `store.js` (файл `*.rpg.json`), `reminders.js` (напоминания и таймер), `args.js` (строгий разбор аргументов) |
| `src/services/accountAssistant.js` | черновики, режимы `approval`/`dry-run`/`auto`, защита от автоотправки, команды владельца |
| `src/utils/` | `logger` (уровни, редактирование), `errors`/`redact` (безопасное описание ошибок), `text` (разбиение), `queue`, `ttlSet`, `safe` |
| `src/ideas/` | генератор идей: `prompt.md` (текст автора), `catalog.js` (пулы искр и 12 приёмов), `spark.js` (сборка, бросок и переброс искры), `recent.js` (недавние искры чата, только в памяти), `bank.js` (банк идей в хранилище «собеседника»), `tools.js` (четыре функции модели), `commands.js` (команды и кнопки для бота и сайта) |
| `src/handlers/reply.js`, `src/handlers/ideas.js` | общий ответ ИИ (очередь чата, индикатор набора, проверка выхода из сессии) и команды/кнопки идей |
| `src/site.js`, `public/` | сайт на `/`: страница, стили и скрипт отдаются из памяти, `GET /api/spark`, заголовки безопасности |
| `scripts/userbot.js` | команды от аккаунта; запускается напрямую, функции экспортированы для тестов |
| `scripts/create-telegram-session.js` | интерактивное создание `TELEGRAM_STRING_SESSION` |

## Решения, которые стоит знать

- **Секреты не в логах и не в ошибках.** Ошибка axios содержит заголовок `Authorization` и весь диалог, поэтому `openrouter.js` превращает любую ошибку в `ApiError` без ссылок на запрос; логгер дополнительно маскирует токен бота, ключ OpenRouter и строки сессий. Тексты сообщений пишутся в лог только при `LOG_MESSAGES=true`.
- **Память пишется не на каждое сообщение.** Изменения помечают хранилище «грязным», запись выполняется раз в `MEMORY_SAVE_DEBOUNCE_MS` асинхронно через временный файл и `rename`; при остановке сбрасывается синхронно. Копия `memory.json.bak` обновляется раз в `MEMORY_BACKUP_INTERVAL_MS`.
- **Ответ пользователю не теряется.** Длинный текст разбивается по абзацам/строкам/словам без разрыва суррогатных пар; повтор генерации делается не более одного раза, одинаковые ответы на разные сообщения не подавляются.
- **Ассистент аккаунта осторожен по умолчанию.** Контакты распознаются по ID/username; черновик отправляется атомарно один раз; `auto` требует allow-list и детерминированно останавливает рискованные ответы. Память ассистента хранится отдельно (`account:<chatId>`).
- **Остановка опроса Telegram — отдельная забота.** В `node-telegram-bot-api@0.67` `stopPolling({ cancel: true })` возвращается сразу, но цикл опроса перезапускает сам себя; поэтому `stopTelegramPolling` сначала поднимает внутренний флаг `_abort`. При обновлении библиотеки это место нужно перепроверить (тест «остановка опроса настоящая»).
- **Сбой при старте не навсегда.** Если `getMe()` не ответил, личность бота запрашивается повторно (до 8 раз, пауза 1, 2, 4 … 60 с): без неё бот не отличит `/cmd@чужой_бот` от своей команды. Ошибки опроса пишутся в лог не чаще раза в минуту (со счётчиком пропущенных и подсказками для 409 и 401).
- **Регулярные выражения над текстом модели — только линейные.** `/[ \t]+\n/` квадратичен на длинной серии пробелов; для обрезки пробелов в конце строк есть `utils/text.trimLineEnds`.
- **gramjs загружается лениво**, только при включённом ассистенте или запуске userbot (около 0,2 с и 40 МБ).
- **Настройки команд владельца не сохраняются** между запусками: `auto` не должен «залипнуть» после перезапуска.
- **Характер выбирается внутри `buildSystemPrompt`, а не заменяет старый.** Поле `persona` чата (`companion` / `classic` / не выбран) решает, чей промпт собирать; классический путь `askAI` не менялся. Текстовый и голосовой обработчики вызывают `companion/engine.respond`: он отдаёт классику прежнему `askAI`, а «собеседника» ведёт через цикл вызовов функций. Сообщения других ботов функций не получают.
- **Модель предлагает, код решает.** Функции не принимают идентификаторов: владелец берётся из Telegram-сообщения, общее состояние привязано к чату. Любое изменение персонажа идёт через `store.change()` (копия → правило → запись на диск → подмена), поэтому отказ правил не оставляет следов. Суточные потолки опыта и золота и таблицы из промпта лежат в `rules.js`.
- **Откат без функций безопасен только до первого вызова.** Если провайдер отвечает «модель не умеет функции», запрос повторяется без них и 10 минут не пробует снова, но лишь пока ни одна функция не выполнилась: изменённое состояние повторно не проигрывается.
- **Случайность идей даёт код, а не модель.** Языковая модель плохо выдаёт случайное, и идеи сползают к одним и тем же; поэтому форму искры (таблица `SPARK_SHAPES`: от двух до четырёх ингредиентов, область всегда первая), сами ингредиенты и приём выбирает `crypto.randomInt` (`ideas/spark.js`, генератор передаётся параметром, тесты подставляют свой), а модель только развивает выпавшее. Это тот же принцип «модель предлагает, код решает», что и у кубика.
- **Чат помнит недавние искры, но только в памяти.** `ideas/recent.js` хранит значения последних искр и приёмов чата, чтобы следующая искра их не повторяла, и последнюю одиночную искру, чтобы модель могла перебросить её часть (`idea_spark` с `reroll`). Карточка `/spark` и функция модели пишут в одну историю, поэтому «поменяй поворот» относится к искре, которую человек видел на карточке. На диск ничего не пишется: перезапуск стоит одного возможного повтора, зато нечего хранить и защищать; `/reset` историю тоже очищает. Сайт истории не ведёт: она привязала бы искры к посетителям.
- **Отказ функции говорит модели, что делать дальше.** `executeTool` добавляет к каждому `{ ok: false, error }` подсказку `hint` из `companion/hints.js`, если функция не дала свою: поправить аргумент, сначала посмотреть список или сказать человеку, что не вышло. Без неё модель либо повторяет тот же неверный вызов, либо пишет «готово» после отказа. Тест ищет коды отказа в исходниках и не даст добавить код без подсказки.
- **Набор функций принадлежит характеру и проверяется кодом.** `toolsFor(persona)` даёт список для запроса, `executeTool` отказывает всему, чего в нём нет (`unknown_tool`): чат идей не доберётся до RPG-функций, а собеседник — до банка идей, даже если модель выдумает вызов. Сообщения других ботов функций не получают.
- **Банк идей — аддитивный ключ того же файла.** `ideas` лежит в хранилище «собеседника» рядом с фактами и ключом `человек в чате`; старый файл без него открывается (`validate` дополняет недостающее), версия не менялась. Идеи личные (`чат:человек`), и `/reset` их не трогает: это созданное человеком, а не память разговора.
- **Один конвейер ответа ИИ.** Текст, команды и кнопки идей идут через `handlers/reply.js` (очередь чата, индикатор набора, проверка, что человек не вышел за время ожидания). Команда, которой нужна модель, превращается в обычный запрос к ней; `/ideas` и `/techniques` строит код.
- **Сайт не может уронить бота и ничего не раскрывает.** Файлы `public/` читаются один раз при старте; если их нет, `/` отвечает прежней строкой, а бот работает. Отдаются только перечисленные маршруты (не папка целиком), всё под CSP без инлайна. `GET /api/spark` не вызывает ИИ и ничего не хранит.
- **Связи между модулями — в одном месте.** `src/lifecycle.js` зависит только от логгера; модули экспортируют хуки (`lifecycleHooks`), а `registerLifecycle` в `src/bot.js` регистрирует их явно, по порядку (не при `require`, чтобы unit-тесты не копили глобальное состояние; повторное имя — исключение при старте). Хуки выполняются по порядку, ошибка одного пишется в лог без текста и не останавливает остальные; вызывающий получает список не справившихся, а не исключение. `/reset` = `forgetChat` (память чата, недавние искры, факты); `/status` = прежние строки + `statusLines` (банк идей, напоминания, лаборатория в личном чате). Новый модуль с данными людей подключается одной строкой регистрации, а не правками в `/reset`, `/status`, выходе и экспорте.
- **Отзыв доступа живёт в `auth.logout`.** Путей выхода несколько (`/logout`, `/login`, подтверждение `/access … blocked`, будущие), а точка, через которую проходят все, одна — `PasswordAuth.logout`. Она сначала закрывает сессию, затем вызывает `onRevoke` (его ставит `src/bot.js`: `lifecycle.revokeUser`), поэтому любой путь гасит одно и то же: сессию лаборатории, inline-меню, кнопки действий. Раньше об этом знал только `/logout`, и после блокировки через `/access` сессия лаборатории оставалась активной. Сбой хука доступ не оставляет открытым.
- **Кнопки под идеями шлют модели слова, а не вызывают функции сами.** «Развей 2» или «💾 2» превращаются в обычный запрос «развей 2» / «сохрани идею 2 в банк» через общий конвейер ответа (очередь, проверка выхода, свой `sourceMessageId` = `cb:<query.id>` на каждое нажатие). Что значит «вторая идея», знает только модель — номер в тексте её ответа; код не парсит идеи из свободного текста и не сохраняет догадки. Кнопки карточки искры, наоборот, работают без модели: искру перебрасывает код. Токен кнопки хранит чат, человека, lease, вид, данные и `message_id`; живёт в памяти: после перезапуска «Кнопка устарела» дешевле, чем хранить и защищать кнопки на диске.
- **У кода искры контрольный знак, зависящий от каталога.** Код хранит не текст искры, а места значений в пулах; если пулы или приёмы поправят, те же места укажут на другие значения. Сумма считается от содержимого каталога (и цифра версии в начале кода — тоже), поэтому старый код после правки отказывает («от прежней версии»), а не превращается молча в другую искру. Испорченный или случайный код отказывает так же: к модели ничего не уходит.
- `node-telegram-bot-api` остаётся 0.67: версия 2.x — полная переписка с другим API. Транзитивная зависимость `request` заменена в `package.json` (`overrides`) на поддерживаемый форк.

## Тесты

`tests/unit` — функции без сети; `tests/integration` — настоящий процесс бота против `tests/helpers/fakeTelegram.js` и `fakeOpenRouter.js` (адреса задаются `TELEGRAM_API_BASE_URL` и `OPENROUTER_BASE_URL`), ассистент и userbot — в процессе со стабом клиента gramjs. Запуск: `npm test`; линтер: `npm run lint`.

## Известные ограничения

- Реальные Telegram и OpenRouter в тестах не используются; доступность моделей и формат STT-эндпоинта проверяются только на живом ключе.
- gramjs (`telegram`) объявлен архивным; его сменная замена `teleproto` не проверялась (нужен доступ к живому Telegram).
- Хранилище памяти — один JSON-файл: для сотен чатов стоит перейти на базу данных.
